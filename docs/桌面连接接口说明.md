# 桌宠 ↔ AstrBot 桌面连接 · 接口说明（v1.0）

> **给主人的一段话：** 这份是桌宠和阿鲸之间「怎么说话」的约定：发什么消息、每条长什么样、出错了怎么说。桌宠这边（本仓库）和阿鲸那边（AstrBot 的桌面适配器插件）各写各的，都对着这份测。阶段 ① 要用的部分写全了，后面阶段的先占个位置。
>
> v1.0 是正式版：合进了阿鲸那边的审阅意见、你 11-06 在 bot 那边定的 4 条，和「连上时桌宠自己的 AI 不主动开口」。两边照这份写代码。以后要改，只加字段、加类型，改完在这里记版本。
>
> 本文件在公开仓库里，只写接口，不写主人的部署和安全细节（那些在主人的私密档案里）。

- 版本：v1.0（2026-11-06，两边确认）。v0.1 由桌宠云端会话起草；v0.2 合进「阿鲸桌宠接入」会话的审阅（「阿鲸产品经理」核过）；v1.0 合进 bot 那边对 v0.2 的回复。
- 依据：工作档案总览「一起看 + 桌宠接入 10 条定稿」、「已确认的连接需求」。

## 1. 分工和范围

| | 谁 | 做什么 |
| --- | --- | --- |
| 客户端 | 桌宠（Electron 主进程） | 主动连上去、配对、把桌面聊天和事件交过去、显示 bot 的回复和指令；连不上时退回自带的大脑，不报错 |
| 服务端 | AstrBot 桌面适配器插件 | 一个插件，里面注册一个平台适配器。桌面是 AstrBot 里**单独的一个会话**（不冒充 QQ 私聊，不直接写库）；验证设备、把消息交给阿鲸、把她的回复推回来 |

阶段 ① 的范围：**连接、配对、聊天（不流式）、可靠投递、离线补交、断线重连、睡觉吃饭的计数（`event.care`）、离线快照（`snapshot.data`）**。

服务端内部做、不需要额外消息的：
- **记忆互通**：桌面会话和 QQ 私聊是两个会话，但记忆是一份。原话上下文两边各存各的；更早的事（原文档案、日记、周记、核心档案、印象、事件索引、长期记忆、翻原文的工具）两边共用，每条原文记下是哪一边说的。
- **跨设备时间线**：另一边最近 6 小时、最多 10 条，临时挂在每条消息后面，不进对话历史（10 条定稿第 5 条，做成配置）。
- **提醒**：只存在 bot 这边（主人 11-06 定的）。桌面上说「3 点提醒我开会」，她照 QQ 的做法用 AstrBot 自带的定时任务记下；到点 bot 两边都发：QQ 一条普通消息，桌面一条 `cmd.say`（`source: "reminder"`）。QQ 上设的提醒也一样两边发。桌宠自己的提醒（bot 不在线时设的、设置页里设的）照旧存在桌宠、自己响。
- **所有设备共用 1 个桌面会话**，每条消息记下是哪台设备（`device_id`）。阶段 ① 只有和 bot 同一台的那 1 台；阶段 ④ 接第二台电脑之前再请主人确认一次。

## 2. 连接

- 协议：WebSocket，只用文本帧，内容是 UTF-8 的 JSON。单帧最大 1 MiB（1～2 MiB 的帧服务端回 4400；超过 2 MiB 的由 WebSocket 库直接关掉，关闭码 1009）。
- 地址：桌宠设置里填，默认 `ws://127.0.0.1:6230/desktop/v1`，设置里可以改端口。
  - 路径里的 `v1` 和信封里的 `v` 都留：同一条路径上加字段、加类型不升版本；只有不兼容的改动才换 `/desktop/v2`。
- 服务端只监听 `127.0.0.1`，**绝不监听 `0.0.0.0`**。阶段 ④（另一台电脑）再加组网工具的私有地址。
- 桌宠这边只允许对本机、局域网、组网工具（`100.64.0.0/10`）地址用 `ws://`，其他地址必须 `wss://`（和 1.6.1 的接口地址规则一致）。
- 服务端在握手时检查：
  - **请求里带 `Origin` 头的一律拒绝**（浏览器里的网页连本机端口一定会带 `Origin`，桌宠的主进程不带）；
  - `Host` 必须是 `127.0.0.1:端口` 或 `localhost:端口`（防 DNS 重绑定）。
- 同一台设备同时只保留一条连接：同一个设备令牌又连上来时，服务端关掉旧的那条（4409）。

## 3. 信封

每一帧都是一个 JSON 对象：

```json
{ "v": 1, "type": "chat.send", "id": "m_01JC8Q3Z4X", "ts": 1762400000000, "data": { } }
```

| 字段 | 说明 |
| --- | --- |
| `v` | 协议大版本，现在是 `1` |
| `type` | 消息类型，见下文 |
| `id` | 发送方生成、全局唯一，≤64 字符（UUID 或 ULID 都行）。用来去重和回执 |
| `ts` | 发送方的时间，毫秒，UTC |
| `data` | 内容 |

- 收到不认识的 `type`：忽略，只记一下条数，不断开（方便以后加新类型）。
- 收到不认识的字段：忽略。
- **两边的日志都只记类型、编号、条数、长度，不记聊天原文、令牌、配对码。**
- 分天、定时：两边都按北京时间，凌晨 4 点分天。`hello.tz` 只用来记诊断。

## 4. 握手和配对

连上以后，桌宠 10 秒内必须先发 `hello`，否则服务端断开（4408）。

### 4.1 `hello`（桌宠 → bot）

```json
{ "v": 1, "type": "hello", "id": "h_01JC8Q", "ts": 1762400000000, "data": {
  "proto": [1],
  "app": "ClaudePet", "app_version": "1.7.0", "platform": "win32",
  "device_name": "书房电脑",
  "tz": "Asia/Shanghai", "tz_offset_min": 480,
  "auth": { "token": "…" }
} }
```

- `auth` 二选一：已经配对过用 `{ "token": "…" }`；第一次配对用 `{ "pair_code": "483920" }`。
- `platform`：`win32` 或 `darwin`。
- `device_name`：主人在桌宠设置里起的名字，默认用电脑名，≤32 字（超了服务端截断）。

### 4.2 `welcome`（bot → 桌宠）

```json
{ "v": 1, "type": "welcome", "id": "w_01JC8Q", "ts": 1762400000123, "data": {
  "proto": 1,
  "device_id": "dev_7f3a",
  "token": "…（只有这次是配对时才有）",
  "server_time": 1762400000123,
  "limits": { "text_max": 4000, "frame_max": 1048576, "batch_max": 200 },
  "reply_timeout_s": 240,
  "features": []
} }
```

- `features`：服务端支持的可选能力。**阶段 ① 是空的**（不流式，见第 7.2 节）。桌宠只用列出来的。
- `reply_timeout_s`：桌宠等一条回答的上限（默认 240 秒，见第 7.2 节）。
- 时间差超过 2 分钟时，桌宠在诊断信息里记一笔。

### 4.3 配对码和设备令牌

- 配对码：主人在 QQ 私聊发「/桌宠配对」拿到，**6 位数字，5 分钟内有效，用一次作废，只认主人**。
- 防猜：
  - 同一个配对码输错 5 次就作废；
  - 每条连接只能试 1 次，错了就断开（4403）；
  - 所有连接合起来每分钟最多试 10 次配对，超了回 4429，`reason` 写 `retry_after=60`。
- 最多 5 台设备；满了「/桌宠配对」会提示先吊销一台。
- 设备令牌：配对成功时服务端生成，至少 32 字节随机数，base64url 编码。服务端**只存它的哈希**。
- **设备令牌等于主人本人**：桌面发来的消息和 QQ 上主人发的一样，能用 bot 里只给主人用的功能。所以桌宠：
  - 用系统加密（safeStorage）存在本机，和 API Key 一样，不进同步盘、不进诊断信息、不放在网址里；
  - 令牌只留在主进程里，**桌宠的网页界面（渲染进程）拿不到**；
  - `chat.send` 的 `text` 里**只放主人自己打的字或说的话**，绝不放屏幕、弹幕、网页内容或桌宠自己生成的话（阶段 ② 会为这些另定专门的字段）。
- 「/桌宠设备」列出设备（名字、平台、上次在线时间、编号后 4 位）；「/桌宠吊销 <编号后 4 位>」吊销那一台：这台设备再连会收到 4401，正连着的立刻被断开。
- 桌宠收到 4401：提示「这台电脑和阿鲸的连接被撤销了，要重新配对」，停止自动重连，退回自带的大脑。

## 5. 心跳和重连

- 桌宠每 30 秒发一次 `ping`（`data` 为空），服务端回 `pong`（`data.ref` = 那条 ping 的 `id`）。10 秒没回就当断了，开始重连。
- 服务端 90 秒没收到任何帧就用 4408 断开（`reason` 写 `idle_timeout`），桌宠照普通断线重连。
- 重连间隔：1、2、4、8、16、30 秒，之后一直 30 秒，每次加一点随机抖动。
- 关闭码 1001（bot 正常关机或重启）、1006（异常断开）：按普通断线重连。
- 收到 4401、4403、4426 时**不自动重连**，等主人处理。
- 连不上、断开期间：桌宠照常用自带的大脑和记忆说话，界面上只在设置页显示「阿鲸不在线」，不弹窗、不报错（连接需求第 4 条）。bot 停了会被自动拉起，一般几分钟内就能重新连上。

## 6. 可靠投递：回执和发件箱

- 下面这些类型**必须回执**：桌宠发的 `chat.send`、`offline.batch`、`event.care`（以后还有别的 `event.*`）；bot 发的 `cmd.say`、`event.care`、`snapshot.data`。
- 收到的一方处理好（服务端：交给阿鲸的会话或存进队列；桌宠：显示出来、排进气泡队列或存好）以后回：

```json
{ "v": 1, "type": "ack", "id": "a_01JC8R", "ts": 1762400000200, "data": { "ref": "m_01JC8Q3Z4X", "ok": true } }
```

  不收的回 `"ok": false, "code": "…"`（错误码见第 12 节），发送方不再重发。处理失败、想让对方重发的，就**不回执**。
- 发送方没收到回执之前，把消息留在**发件箱**里；重连后用**同一个 `id`** 重发。收到的一方按 `id` 去重：同一个 `id` 再来，直接再回一次回执，不重复处理。去重记录至少保留 7 天。
- 桌宠的发件箱存在本机（经 `store.js`，先写临时文件再替换），最多 500 条或 7 天，超出的丢掉最旧的，只在诊断信息里记丢了几条。
- 回执只表示「收到了」，不表示「回答了」。回答走第 7 节。

## 7. 聊天

### 7.1 `chat.send`（桌宠 → bot）

```json
{ "v": 1, "type": "chat.send", "id": "m_01JC8Q3Z4X", "ts": 1762400000000, "data": {
  "text": "今天好累啊",
  "input": "text"
} }
```

- `text`：**只放主人自己打的字或说的话**（见第 4.3 节）。≤ `limits.text_max`（4000）字，超过的桌宠先截断。
- `input`：`text`（打字）或 `voice`（语音识别出来的，可能有错字；bot 会给她挂一句临时提示）。
- 桌宠不自己合并消息：主人发一条就交一条 `chat.send`。
- 以后的阶段会在 `data` 里加字段（比如一起看时的播放点、阶段 ② 的截图 `images`），服务端照常忽略不认识的字段。阶段 ① 收到带 `images` 的 `chat.send`，bot 只回答文字部分，图丢掉，回执照常 `ok: true`。

### 7.2 回复：`chat.done`（bot → 桌宠）

**阶段 ① 不流式**：bot 发出前要过一道过滤（删工具调用标记、删外泄的草稿、救回空回复），要等整条回复出来才能做，所以只发 `chat.done`，不发 `chat.delta`（`chat.delta` 留着，以后要做再开）。

```json
{ "v": 1, "type": "chat.done", "id": "r_01JC8T", "ts": 1762400003000, "data": {
  "reply_to": "m_01JC8Q3Z4X",
  "merged": ["m_01JC8Q3Z4X"],
  "parts": [
    { "text": "辛苦啦～今天忙什么了？" }
  ],
  "emotion": { "name": "担心", "level": 1 }
} }
```

- `parts`：一条或几条气泡，按顺序显示。每一项二选一：
  - 文字 `{ "text": "…" }`：给人看的文字，不带任何隐藏标记；桌宠照样过一遍 `ai-parse.js` 的 `visible()` 兜底；
  - 图 `{ "image": { "mime": "image/png", "sha256": "…", "size": 12345, "data": "<base64>" } }`：她回答里的图。单张 ≤700 KB，桌宠按 sha256 校验、缓存。
  - 回复被过滤成空时 `parts` 是空数组，桌宠什么都不显示。
- `emotion`：可选，阿鲸的 8 个情绪名之一（开心、得意、上头、平静、无聊、烦、委屈、担心），强度 1～3。bot 本机算，算不出来就不带。桌宠用它选表情和动作。
- **排队和合并**（和 QQ 私聊现在一样）：同一个会话的回答一条一条来。她正在答、中途在调工具时新来的那条，会被并进正在写的这条回答里，列在 `merged` 里，不再单独回。
- **每条 `chat.send` 恰好有 1 个结果**：它自己的 `chat.done`；或者出现在另一条 `chat.done` 的 `merged` 里；或者 `chat.error`。
- **等多久**：桌宠等 `reply_timeout_s`（240 秒）没收到结果，就当这条失败，对这一句改用自带的大脑回答。之后迟到的 `chat.done` 照常显示成一条气泡。（bot 一次模型请求最多 45 秒，她调工具时一条回答会超过 45 秒。）
  - 桌宠自带大脑替她答的那句，用 `offline.batch` 交给 bot（`role: "pet"`，`reply_to` 填它替答的那条 `chat.send` 的 `id`），让她知道桌宠替她说过什么。**只交桌宠替答的那句**，主人那句已经走 `chat.send` 到了 bot，不再交。连着的时候也可以发，不用等重连。
- 出错：

```json
{ "v": 1, "type": "chat.error", "id": "e_01JC8T", "ts": 1762400003000, "data": {
  "reply_to": "m_01JC8Q3Z4X", "code": "model_failed", "retry": true
} }
```

  - 模型出错时，AstrBot 本来会回一句固定的报错话；桌面上 bot 改发 `chat.error`，那句报错话不发到桌面。
  - `chat.error` 没有 `merged`：出错的那条回答里并进来的每条，各发 1 条 `chat.error`。
  - bot 收下一条 `chat.send` 900 秒还没答完，也发 `chat.error`（`model_failed`, `retry: true`）兜底。
  - 阶段 ① 不会发 `busy`（同一个会话只排队，不拒绝）。
  - 桌宠收到 `retry: true`：对这一句改用自带的大脑回答，并在旁边标明这句是桌宠自己说的（措辞到时候给主人看）。

### 7.3 她回答中途另发的东西

她回答中途用工具另发的一句、生成的图，阶段 ① 走 `cmd.say`（`source: "reply"`，带 `reply_to`）。`chat.done` 里只放这条回答本身。

### 7.4 语音

阶段 ① 桌宠自己用 Edge / Kokoro 念文字气泡，bot 不发音频；图不念。一起看时默认不念（10 条定稿第 3 条）。

## 8. bot 发给桌面的其他话：`cmd.say`（bot → 桌宠）

```json
{ "v": 1, "type": "cmd.say", "id": "s_01JC9A", "ts": 1762400100000, "data": {
  "source": "reminder",
  "reply_to": null,
  "parts": [ { "text": "3 点啦，去开会咯" } ],
  "emotion": { "name": "平静", "level": 1 },
  "expires_at": 1762401900000
} }
```

- `parts` 的格式和 `chat.done` 一样（文字或图）。`reply_to` 可选。
- `expires_at`：过了这个时间还没显示出来就丢掉。
- 阶段 ① bot 会发的 `source`：

| `source` | 是什么 | `expires_at` |
| --- | --- | --- |
| `reminder` | 到点提醒（QQ 那边同时也发） | 到点后 30 分钟 |
| `sticker` | 回答后补发的表情包（`parts` 里一张图，带 `reply_to`） | 发出后 2 分钟 |
| `reply` | 回答中途另发的话或图（第 7.3 节，带 `reply_to`） | 发出后 10 分钟 |

- 以后阶段才发的 `source`：`proactive`（主动找你）、`care`（关心睡觉吃饭）、`watch`（一起看）。阶段 ① 主动消息照旧只发 QQ，按在不在电脑前分两边是阶段 ③ 的事。
- 发给哪台：阶段 ① 发给最近一次发过消息、现在在线的那台；阶段 ③ 改成按 `event.presence`。
- 必须回执。桌宠显示了回 `ok: true`；因为过期、全屏勿扰之类没显示，回 `ok: false` 和原因（`expired` / `dnd`）：提醒 QQ 那边已经发过了，不补；表情包丢掉。

## 9. 离线补交：`offline.batch`（桌宠 → bot）

bot 不在线期间，主人照样和桌宠聊（用的是桌宠自带的大脑）。重连成功后，桌宠把这段时间的对话一次交过去：

```json
{ "v": 1, "type": "offline.batch", "id": "b_01JC9B", "ts": 1762403600000, "data": {
  "from": 1762400000000, "to": 1762403500000,
  "items": [
    { "id": "m_01JC90", "ts": 1762401000000, "kind": "chat", "role": "user", "input": "text", "text": "我去吃饭了" },
    { "id": "m_01JC91", "ts": 1762401002000, "kind": "chat", "role": "pet", "text": "去吧去吧，吃饱再回来～" },
    { "id": "m_01JC95", "ts": 1762402000000, "kind": "chat", "role": "pet", "reply_to": "m_01JC94", "text": "（阿鲸没接上时桌宠替她答的一句）" }
  ]
} }
```

- `role`：`user`（主人说的）或 `pet`（桌宠自带的大脑说的）。
- `kind`：可选，默认 `chat`；阶段 ③ 的事件（重摔、两小时没人理……）以后也放进来，用 `kind` 区分。
- `input`：可选，`text` / `voice`。
- `reply_to`：可选。桌宠在连着的时候替她答（等回答超时或 `chat.error`，第 7.2 节）的那句带上它替答的 `chat.send` 的 `id`。
- 什么时候发：重连成功后补交；连着的时候替她答了一句，也立刻发。
- 每条 `text` ≤ `text_max`；图片和转发写成 `[图片]`、`[转发]`。
- 一批最多 `limits.batch_max`（200）条，超了回执 `ok: false, code: "too_long"`，桌宠拆小了再发。每批都要回执。
- 服务端怎么记：
  - 进原文档案：每条记下哪一边（桌面）、来源（离线补交）、谁说的、自己的 `ts`；
  - 桌宠说的那几句标「离线时桌宠说的」；带 `reply_to` 的标「阿鲸没接上时桌宠替她答的，不是你说的」。写日记、印象这些时都不算阿鲸自己说过的话；主人那几句照常算主人说的；
  - 不进桌面会话的对话历史（不让她把桌宠的话当成自己说过的）；跨设备时间线里会带上，带同样的标；
  - **只记不答**：不回答、不触发主动消息；
  - 去重：按 batch 的 `id`，也按每条 item 的 `id`，重发时分批不一样也不会重复记。

## 10. 睡觉、吃饭的计数：`event.care`（双向，阶段 ①）

10 条定稿第 6 条：睡觉 0:30 起问，每晚两边合起来最多 2 次；吃饭午饭 11～14 点、晚饭 17～20 点，每顿两边合起来最多 1 次；主人回过或说了「别管」就不再问；不用「该……了」的口气；「该休息」只在桌宠上说。

```json
{ "v": 1, "type": "event.care", "id": "c_01JCA0", "ts": 1762446600000, "data": {
  "kind": "sleep", "slot": "2026-11-06/night", "action": "asked", "side": "desktop"
} }
```

- `kind`：`sleep` 或 `meal`。
- `slot`：日期 + `night` / `lunch` / `dinner`。日期按凌晨 4 点分天，11-07 00:30 问的算 `2026-11-06/night`。
- `action`：`asked`（问了 1 次）、`answered`（主人回了）、`stop`（主人说别管）、`state`（现状）。
- `side`：这件事发生在哪边，`qq` 或 `desktop`。
- **bot 记总账**：
  - 收到桌宠的 `asked` / `answered` / `stop` 以后，bot 回一条 `action: "state"`；连上后 bot 也先发当天各格的 `state`。
  - `state` 的 `data` 另带 `asked_qq`、`asked_desktop`、`answered`、`stopped`、`limit`。
  - 桌宠问之前看最新的 `state`；离线期间桌宠自己计，连上后照原来的 `ts` 补发（走发件箱）。
  - bot 不新加主动去问，只计她自然问的；到了上限、主人回过或说别管以后，bot 给她挂一句「别再提」的临时提示。
  - 1 点以后 bot 不主动发消息，所以深夜基本由桌宠问。
- 必须回执。bot 处理失败时不回执，桌宠留在发件箱里重发。

## 11. 离线快照：`snapshot.data`（bot → 桌宠，阶段 ①）

10 条定稿第 7 条：bot 不在线时桌宠用的那份「备份记忆」。

```json
{ "v": 1, "type": "snapshot.data", "id": "p_01JCA1", "ts": 1762400000000, "data": {
  "made_at": 1762400000000,
  "profile": "…",
  "impression": "…",
  "diary":   [ { "date": "2026-11-02", "text": "…" } ],
  "weekly":  [ { "week": "2026-W44", "text": "…" } ],
  "hobbies": [ { "name": "…", "text": "…" } ],
  "mood":    { "name": "平静", "line": "…" },
  "recent":  [ { "ts": 1762399000000, "side": "qq", "who": "user", "text": "…" } ],
  "filtered": { "diary": 0, "weekly": 0, "profile": 0, "impression": 0, "hobbies": 0 }
} }
```

- 什么时候发：连上时发 1 次，之后每小时 1 次。必须回执。
- 放什么：核心档案（含主人的手写区）、常驻的印象、本周日记、前两周周记、爱好档案、当前心境、两边最近 24 小时原话。
- 不放什么：群里来的、钱和投资、健康、聊天里提到的其他人（这 4 样 bot 从日记、周记、核心档案、印象、爱好档案里剔掉，`filtered` 只记剔了几句，不带内容）；24 小时以前的完整原文。
- `recent`（24 小时原话）**不过滤**（主人选的）：每条带时间、哪一边（`qq` / `desktop`）、谁说的（`user` 主人、`ajing` 阿鲸、`pet` 离线时桌宠），长的截到 100 字，图片和转发写成 `[图片]`、`[转发]`。
- 大小：一份 ≤150 KB（bot 那边用真数据试算约 31 KB）。
- 桌宠这边：**只留最新 1 份，只存本机**的用户数据目录（经 `store.js`），不放进仓库目录、不放进共享文件夹或同步盘、诊断信息不带。离线时提示词里告诉她「现在只有备份记忆，想不起来就照实说，别编」。
- bot 那边以后加了时间线、月记，快照跟着换；字段只加不删。

  13. 计数器两边合起来算：桌面问 1 次 + QQ 问 1 次 = 当晚 2 次，第 3 次不问。

  15. 被并进来的消息只出现在 `merged` 里，不单独回。
  16. 等满 `reply_timeout_s` 没结果：桌宠自带大脑回答；迟到的 `chat.done` 照常显示。
  17. 桌宠自己生成的话、离线补交的话，不会被当成主人的指令去调 bot 里只给主人用的功能（bot 那边测）。

## 16. 阶段 ② 一起看（v1.1-draft，2026-11-07，两边已对过，照这份写）

> 桌宠云端会话起草，「阿鲸桌宠接入」11-07 审过并补了 4 处（看完那句不查播放点、`features` 判断、打字信号、`cmd.mode` 只回执），已合进来。两边都在开发分支照这份写，上线和发版要主人另外点头。阶段 ② 上线时并进上面各节，改成 v1.1。依据：10 条定稿第 2、3 条，阿鲸自己写的一起看需求，11-07 主人同意开工时的省钱思路。只写接口，不写主人的部署和隐私细节。

### 16.1 链路和开关

B 站视频页里的**油猴脚本** →（本机 HTTP，只在这台电脑上）→ **桌宠** →（本说明的 WebSocket）→ **bot**。

- 脚本只和桌宠说话，bot 的地址和设备令牌只在桌宠里。
- **`welcome.features` 里有 `"watch"` 时**，桌宠才发 `event.watch`、`event.mode`、`event.typing`、`event.point`；有 `"images"` 时才在 `chat.send` 里带截图。阶段 ① 的 bot `features` 是 `[]`，所以桌宠连着阶段 ① 的 bot 时一起看什么都不发。
- 桌宠没连上 bot 时，一起看什么都不说（10 条定稿第 2 条），脚本照常报进度，桌宠只丢掉。
- 阶段 ② 只做 B 站视频页（`www.bilibili.com/video/*`、`/bangumi/play/*`）。

### 16.2 桌宠 ↔ 油猴脚本（本机接口，bot 不用管）

- 桌宠在 `127.0.0.1:6231` 开一个 HTTP 接口（设置里可改端口），**只监听本机**，检查 `Host` 是 `127.0.0.1:端口` / `localhost:端口`。
- 每台电脑一个随机口令：桌宠设置页「一起看」里有「复制油猴脚本」按钮，复制出来的脚本里已经带着这台电脑的口令和端口。脚本每次请求带 `X-Pet-Key`，口令不对的一律 403。脚本用 `GM_xmlhttpRequest`，B 站网页自己的代码碰不到这个接口。
- `POST /watch/v1/event`，请求体 ≤16 KB：

```json
{ "kind": "heartbeat", "video": { "site": "bilibili", "bvid": "BV1xx411c7mD", "cid": 123456, "p": 1, "title": "（视频标题）", "dur": 1325.4 },
  "t": 312.6, "paused": false, "rate": 1.25, "hidden": false, "from": null, "done": [] }
```

  - `kind`：`heartbeat`（播放中每 5 秒）、`play`、`pause`、`seek`（带 `from`）、`rate`、`ended`、`switch`（换了视频）、`hidden` / `visible`（标签页藏起来 / 回来）、`leave`（关掉页面）。除了心跳，其他都立刻发。
  - 番剧页：`cid` 从页面的 `epInfo` 取，`bvid` 有就带，另带网址里的 `ep`（`/bangumi/play/ep12345` 的 12345）。
  - **`cid` 可能是 0**：页面里的数据对不上当前视频时（比如在页面里点了推荐视频、页面数据还是上一个的），脚本宁可不填，免得报错视频。bot 那边这时按 `bvid` + `p`（或 `ep`）自己查。
  - 回：`{ "ok": true, "cmd": [ { "id": "j_…", "type": "seek", "t": 452 } ] }`。`cmd` 只在主人点了「跳过去」以后才有；脚本执行完，下一次请求在 `done` 里带上这个 `id`。**脚本只在桌宠让它跳时才改进度，bot 永远碰不到主人的播放器**（阿鲸需求：「我指一下 + 他点一下」）。
- 脚本**不读弹幕、不读字幕**（bot 自己拉，见 16.4），网友写的字不经过桌宠的通道。
- 桌宠 15 秒收不到心跳，就当主人不看了（发 `leave`）。

### 16.3 进度：`event.watch`（桌宠 → bot）

```json
{ "v": 1, "type": "event.watch", "id": "w_01JD…", "ts": 1794000000000, "data": {
  "kind": "progress",
  "video": { "site": "bilibili", "bvid": "BV1xx411c7mD", "cid": 123456, "p": 1, "title": "（视频标题）", "dur": 1325.4 },
  "t": 312.6, "paused": false, "rate": 1.25, "from": null,
  "mode": "normal", "hourly_max": 25
} }
```

- `kind`：`start`（开始看一个视频，第一次报）、`progress`（播放中**每 10 秒合并一条**）、`play`、`pause`、`seek`（带 `from`）、`rate`、`ended`、`leave`（切走、关掉、标签页藏起来超过 10 秒、心跳断了）。状态变化立刻发。**`leave` 以后回到同一个视频，再发一次 `start`**（bot 按 `bvid + cid` 认成同一次观看，30 分钟内接着算，「每个视频几句」不重新数）。
- `mode`、`hourly_max`：当前档位（见 16.6），每条都带。
- **只有 `start`、`ended`、`leave` 必须回执**（进发件箱，看完留记录要用）；`progress`、`play`、`pause`、`seek`、`rate` 不回执、不进发件箱，没连上就丢。
- bot 那边怎么用：播放中当前点 = `t + (现在 − 信封 ts) / 1000 × rate`；30 秒没收到这个视频的任何 `event.watch` 又没暂停，就当卡住了、不说话；心跳本身不调模型。每秒超过 2 条的多余那几条忽略；`title` 超过 80 字截断；字段不合格的那条忽略、只计数，不断连接。

### 16.4 字幕和弹幕：bot 自己拉

bot 按 `bvid` / `cid` 拉带时间的字幕和整池弹幕，刷屏点也在 bot 那边算。每次要她说话时，只把播放点前 90 秒、最多 40 行挂进那一次请求，不进聊天历史（11-07 的省钱思路）。页面上飘的弹幕和 bot 拉到的是同一池，脚本不用读，桌宠不传。

### 16.5 一起看时主人说话：`chat.send.data.context.watch` 和 `event.typing`

主人在看视频（最近 30 秒内有心跳、没 `leave`）时在桌面上说话，`chat.send` 带上：

```json
"context": { "watch": { "bvid": "BV1xx411c7mD", "cid": 123456, "t": 312.6, "paused": false } }
```

- `text` 里照旧只放主人自己打的字或说的话（第 4.3 节）。回答走普通的 `chat.done`，不受 16.7 的丢弃规则管。
- 话多档「主人正在打字就先回主人」用的打字信号：

```json
{ "v": 1, "type": "event.typing", "id": "y_01JD…", "ts": 1794000000000, "data": { "active": true } }
```

  主人在看视频时（同上），聊天框从空变成有字发 `true`，清空或发出去发 `false`，同一状态 5 秒内不重复发；没在看视频时不发（发过 `true` 的照样补一个 `false`）。不回执、不进发件箱，没连上就丢。bot 收到 `true` 后最多压 60 秒不说话，60 秒内没再收到就当 `false`。

### 16.6 三档：`event.mode`（桌宠 → bot）和 `cmd.mode`（bot → 桌宠）

```json
{ "v": 1, "type": "event.mode", "id": "o_01JD…", "ts": 1794000000000, "data": { "mode": "chatty", "hourly_max": 25, "by": "settings" } }
```

- `mode`：`quiet`（安静）/ `normal`（正常，默认）/ `chatty`（话多）。`hourly_max`：话多档每小时最多几句，默认 25，10～60。
- 桌宠设置里改了、连上的时候，发 `event.mode`（必须回执）。
- 主人在聊天里说「安静看片」「随便说」这类话，bot 识别以后发 `cmd.mode`（**只认带 `context.watch` 的那条消息**，平时随口说「你随便说」不会改档位）（同样的 `data`，`by: "chat"`，必须回执）。桌宠改设置、界面跟着变，**回执 `ok: true` 就算改好了，不再另发 `event.mode`**。
- 各档的数字 bot 那边控（10 条定稿第 2 条）：
  - 正常：每视频 ≤3 句、每句 ≤30 字；
  - 话多：两句至少隔 60 秒，刷屏插队至少隔 20 秒，每句 ≤50 字，每小时上限用 `hourly_max`；暂停时说 1 句就等，暂停超过 5 分钟不说；主人在打字时先等；
  - 安静：只在看完给 1 条小结，最多 3 点。

### 16.7 她说的话：`cmd.say` 的 `source: "watch"`

```json
{ "v": 1, "type": "cmd.say", "id": "s_01JD…", "ts": 1794000000000, "data": {
  "source": "watch", "parts": [ { "text": "这段弹幕笑死" } ],
  "watch": { "bvid": "BV1xx411c7mD", "t": 315.0 },
  "emotion": { "name": "开心", "level": 2 }, "expires_at": 1794000020000
} }
```

- `watch.t`：这句话说的是哪个点（一般是生成时的当前点；「高能」那句是刷屏那 10 秒的起点）。`expires_at` 是发出后 20 秒。两句之间 bot 至少隔 10 秒。
- **锚点里带什么**：有 `bvid` 时带 `bvid`、`p`、`cid`（例：`{ "bvid": "BV1xx411c7mD", "p": 1, "cid": 123456, "t": 315.0 }`）；`bvid` 是空的（番剧）时带 `ep`（整数）、`p`，`cid` 可能是 0（例：`{ "bvid": "", "ep": 12345, "p": 1, "cid": 0, "t": 312.0 }`）；看完那句和安静档小结另带 `"end": true`。
- **认「同一个视频」**：锚点有 `bvid` 就比 `bvid`；`bvid` 是空的就比 `ep`；锚点带了 `p`（分 P）就也比 `p`。都对不上才回 `stale`。
- 桌宠显示前再查一次：同一个视频、没关掉；主人当前播放点和 `t` 差不超过 20 秒；暂停时只有话多档才显示；没过 `expires_at`。不满足就回执 `ok: false, code: "stale"`（bot 只计数，不重发）。
- **例外：看完那句和安静档的小结**带 `"end": true`（`{ "bvid": "…", "t": 1325.4, "end": true }`），桌宠**只查没过 `expires_at`**，不查播放点、暂停、换没换视频（看完以后页面可能停住或自动连播了）。正常档看完那句 `expires_at` 是发出后 60 秒，安静档小结是 10 分钟。小结最多 3 行（一个 part，行之间用 `\n`，每行 ≤30 字）；**带 `end` 的气泡最多显示 3 行、停 12 秒**，别的照旧 2 行、8 秒。桌宠没连上时，bot 留着小结，等主人下次在桌面或 QQ 私聊说话时再提。
- 只有文字：bot 不配语音、不补表情包（回答主人的话后面照常可能有 `source: "sticker"`）。
- 显示：气泡最多 2 行、停 8 秒；**默认不念**，设置里开了「一起看时也念出来」才念（10 条定稿第 3 条）。

### 16.8 她指他点：`cmd.point`（bot → 桌宠）和 `event.point`（桌宠 → bot）

```json
{ "v": 1, "type": "cmd.point", "id": "k_01JD…", "ts": 1794000000000, "data": {
  "bvid": "BV1xx411c7mD", "cid": 123456, "t": 452.0, "text": "07:32 这段你一定要看", "expires_at": 1794000300000
} }
```

- bot 那边：每 5 分钟最多 1 次，只指有字幕或弹幕刷屏的点，`expires_at` 是发出后 5 分钟。`text` 是「07:32 这段可以跳过去看看」这种格式，和她那句 `cmd.say` 是两个气泡，`cmd.point` 在后面发。番剧时 `bvid` 为空，带 `ep`、`p`，`cid` 可能是 0；认视频的规则同 16.7。
- 桌宠弹一个带「跳过去」按钮的气泡（停 15 秒，或者到主人播放过了那个点）。必须回执（显示了 `ok: true`；过期、换了视频回 `ok: false`）。
- 主人点了「跳过去」，桌宠让脚本跳到 `t`，然后发：

```json
{ "v": 1, "type": "event.point", "id": "q_01JD…", "ts": 1794000010000, "data": { "ref": "k_01JD…", "action": "jumped" } }
```

  `action`：`jumped`（点了）、`ignored`（气泡消失也没点）。必须回执，bot 记进看完的记录。

### 16.9 截图

- **主人开口才发**（`features` 有 `"images"` 时）：聊天窗里按了「看屏幕」再发消息、或右键「看看我在看什么」，`chat.send` 带一张图：`data.images: [{ "mime": "image/jpeg", "sha256": "…", "size": 123456, "data": "<base64>" }]`，最多 1 张，桌宠先压成 JPEG，长边 ≤1600 像素、≤700 KB。右键那种没有主人打的字，`text` 填空字符串。她看图回答，bot 只存描述、不存原图。
- **不是主人开口的截图**（自动看屏幕）：留着 `event.screen`（`{ reason, app, title, image }`），**不放进 `chat.send`**，免得 bot 把屏幕上的东西当成主人的话（审阅 B 段第 3 条）。阶段 ② 做不做等产品经理问主人；定之前 bot 收到会回 `ok: false, code: "not_allowed"`、图不看不存，所以**桌宠这边先不发**，连着 bot 时自动看屏幕照旧停着（11-06 主人定的）。
- `cmd.look`（bot 要截图）：阶段 ② 不做，名字先留着。
- 桌宠不存截图，发出去就丢。
- Mac 上截不到图（录屏权限失效）时，桌宠给主人看得见的提示，附「打开系统设置」按钮。

### 16.10 看完留记录

bot 那边记（11-05 说好的）。桌宠这边给的材料：`event.watch` 的 `start` / `seek` / `ended` / `leave`（拖过的区间、看完没看完）、`context.watch`（主人说话时的播放点）、`event.point`。不另加消息。

## 17. 阶段 ③ 在不在电脑前、心情、动作（v1.2-draft，2026-11-12，桌宠云端起草，等「阿鲸桌宠接入」审）

> 依据：10 条定稿第 6、8、9 条，日志 ⑱ 的情绪规则，第 13 节预留的那几行。只写接口，不写主人的部署和隐私细节。两边对过以后照这份写；上线和发版要主人另外点头。下面标「提议」的地方等 bot 那边回话。

### 17.1 开关：`welcome.features`

| `features` 里有 | 桌宠发 | bot 发 |
| --- | --- | --- |
| `"presence"` | `event.presence` | 主动消息按在不在电脑前分两边（17.3）、`cmd.quiet` |
| `"mood"` | `event.emotion` | `cmd.mood` |
| `"act"` | — | `cmd.act` |

三项可以分开上线。没有的那项桌宠照阶段 ② 的样子，不发也不认。

### 17.2 在不在电脑前：`event.presence`（桌宠 → bot）

```json
{ "v": 1, "type": "event.presence", "id": "p_01JE…", "ts": 1794100000000, "data": {
  "state": "here",
  "why": "active",
  "idle_s": 12,
  "away_s": 0,
  "watching": false,
  "front": { "app": "Google Chrome", "title": "（前台窗口标题，≤80 字）" }
} }
```

- `state`：`here`（在）/ `away`（不在）。
- `why`：`start`（刚连上时报一次当前状态）、`active`（有键盘鼠标动静）、`idle`（10 分钟没动）、`locked`（锁屏）、`sleep`（电脑睡眠）、`video`（没动但在放视频，算在）、`front`（只是前台程序或标题变了）。
- 判断规则（定稿第 6 条）：
  - 锁屏、睡眠：立刻 `away`；
  - 10 分钟没有键盘鼠标动静：`away`，**除非在放视频**（`watching: true`，算 `here`，`why: "video"`）；
  - 回来（解锁、唤醒后有动静、或空闲后又动了）：`here`，`away_s` 填离开了多少秒，bot 用它决定说不说「你回来啦」。
- `watching`：在放视频。来源：一起看脚本 30 秒内有心跳且没暂停；Mac 上有程序拿着「不许显示器睡眠」（浏览器、播放器放视频时会拿）；Windows 上前台窗口全屏。
- `front`：前台程序名和窗口标题（定稿第 8 条：默认都报，标题主人可以在设置里关掉，关了就不带 `title`；程序名也可以关，关了整个 `front` 不带）。`away` 时不带 `front`。
  - 程序名：Windows 是进程名（`chrome`、`QQ`），Mac 是程序显示名（`Google Chrome`、`微信`）。
  - 标题超过 80 字截断。
- 什么时候发：连上（`welcome` 之后）报一次 `why: "start"`；`state` 变了立刻发；只是 `front` 变了的，**合并成最多每 15 秒一条**。不定时心跳。
- 不回执、不进发件箱，没连上就丢；重连后照样先报一次 `start`。
- bot 那边：连接断了就当桌面 `away`。`front` 只用来知道主人在干什么，进不进记忆、怎么用由 bot 定；**提议**：`title` 不进长期记忆，只在当时的对话里参考。

### 17.3 主动消息按在不在分两边（`cmd.say` 的 `proactive`）、「别吵我」（`cmd.quiet`）

- bot 主动找主人（闲聊、「你回来啦」、想起什么事）时：最近一条 `event.presence` 是 `here` 就发桌面（`cmd.say`，`source: "proactive"`），不在就发 QQ，不两边都发（定稿第 6 条）。`expires_at` 提议发出后 10 分钟。
- 到点提醒、余额不够照旧两边都发；睡觉吃饭的关心照阶段 ① 的 `event.care`；「该休息」只在桌宠说（定稿第 6 条），bot 不管。
- **发到桌面但主人刚好走开了**：桌宠收下、回执 `{ "ok": true, "held": true }`，等主人回来（`here`）再显示；回来时已经过了 `expires_at` 就不显示了。bot 收到 `held` **不改发 QQ**（定稿：「回来再提一次，不追发 QQ」）。
- 连着 bot 时桌宠自己的 AI 照旧不主动开口（第 15 节）；阶段 ③ 以后「你回来啦」和闲聊由 bot 来说。
- 「别吵我」：主人在任一边说了，bot 判断出来，发：

```json
{ "v": 1, "type": "cmd.quiet", "id": "q_01JE…", "ts": 1794100000000, "data": { "until": 1794107200000 } }
```

  - 必须回执。到 `until` 之前，桌宠自己的碎碎念、「该休息」、深夜和饭点的关心都不说；到点提醒照常（那是主人自己要的）。`until: 0` 表示提前结束。bot 那边自己也不发 `proactive`。

### 17.4 桌宠的身体刺激：`event.emotion`（桌宠 → bot）

```json
{ "v": 1, "type": "event.emotion", "id": "f_01JE…", "ts": 1794100000000, "data": {
  "name": "委屈", "level": 1, "cause": "drop", "text": "被摔疼了"
} }
```

| `cause` | 什么时候 | 情绪 | 桌宠这边限量 |
| --- | --- | --- | --- |
| `drop` | 被拎起来甩、落地摔得重（和现在说「哎哟」的那一下是同一个判断） | 委屈 1 | 1 分钟最多 1 次 |
| `poke` | 3 秒内连戳 5 下，她生气了 | 烦 2 | 每次生气 1 次 |
| `calm` | 她生气时摸头，消气了（新加的反应） | 开心 1 | 每次生气 1 次 |
| `ignored` | 主人在电脑前（`here`，不在看视频）却 2 小时没理桌宠（没在桌面上聊天，没点、没摸、没拎） | 无聊 1 | 一段没理只记 1 次，理了才重新算 |

- 只影响她的心情（bot 算）和表情、台词，**不加减亲密度**（定稿第 9 条）。
- `text` 是给 bot 看的原因，≤20 字。
- 不回执、不进发件箱。**提议**：没连上时，记进下一次的 `offline.batch`（`kind: "emotion"`，字段同上），bot 只记不算进当前心情；超过 1 小时的丢掉。
- bot 那边可以不认：比如主人 2 小时里在 QQ 上和她聊过，`ignored` 就不算（桌宠只知道桌面这边）。

### 17.5 心境：`cmd.mood`（bot → 桌宠）

```json
{ "v": 1, "type": "cmd.mood", "id": "d_01JE…", "ts": 1794100000000, "data": {
  "name": "无聊", "level": 2, "until": 1794103600000
} }
```

- bot 每小时合成的心境（日志 ⑱）。连上（`welcome` 之后）发一次当前的，之后变了才发。必须回执；桌宠只认 `ts` 最新的一条。
- 桌宠用它决定**平时**的样子（待机表情、闲着时做哪些小动作多一点、固定碎碎念挑哪几句），不显示文字。被戳、摸头这些当场的反应照旧本地演。
- 断开以后桌宠留着最后一个心境到 `until`（没有就 2 小时），之后回到平静。
- 桌宠现在有的表情和动画对不全 8 个名字：开心、得意、上头有开心的立绘和动画；无聊用打哈欠、东张西望；烦用生气；平静照常；**委屈、担心还没有专门的画**，先用思考、闭眼的立绘代替，以后补画。

### 17.6 指挥动作：`cmd.act`（bot → 桌宠）

```json
{ "v": 1, "type": "cmd.act", "id": "a_01JE…", "ts": 1794100000000, "data": { "name": "挥手打招呼", "expires_at": 1794100060000 } }
```

- `name`：`design/亲密度与事件.xlsx`「下拉选项」表「动作」列的 18 个名字之一（待机、东张西望、原地走路、思考中、说话、挥手打招呼、被摸头、被点开心、傲娇生气、睡觉、打哈欠伸懒腰、吃白饭、到点提醒、看屏幕、敲键盘、吐泡泡、余额充足、余额见底）。女仆装按同一个意思找对应的片段。
- 必须回执：做了 `ok: true`；没做 `ok: false` 加 `code`：`unknown`（不认识、或这身衣服没有这个动作）、`busy`（正被拎着、正在掉、正在睡）、`away`（主人不在，做了也没人看）、`expired`、`rate`（太密，提议每分钟最多 1 个）。
- 动作不带台词；要说话就另发 `cmd.say`。

### 17.7 桌宠这边自己改的（bot 不用管）

- 生气时摸头会消气（`calm`），配几句新台词（给主人看）。
- 设置页「连接阿鲸」里加两个勾：「告诉阿鲸我在用什么程序」「……也告诉她窗口标题」，默认都勾上。
- 被 `held` 的话，主人回来时显示。
- 不连阿鲸时，桌宠自己深夜那句改成关心地问一句（日志里定的口气），不说「该睡了」。
- 16.5 的打字信号改成只在主人看视频时发（1.7.0 已经这样）。

### 17.8 测试约定（两边都要过）

1. 连上先收到 `event.presence` `why: "start"`；锁屏立刻 `away`；解锁有动静后 `here`，`away_s` 对得上。
2. 10 分钟不动：`away`；一起看在播放时不动：仍是 `here`、`why: "video"`。
3. 只换前台窗口：`why: "front"`，15 秒内最多 1 条；关掉「窗口标题」后不带 `title`。
4. `here` 时 bot 的主动消息只到桌面；`away` 时只到 QQ；发到桌面时刚好走开：回执 `held`，回来才显示，过期不显示，QQ 不补。
5. `cmd.quiet` 期间桌宠的碎碎念、「该休息」不出现，到点提醒照常；`until: 0` 恢复。
6. 连戳 5 下：`event.emotion` 烦 2；接着摸头：开心 1；重摔：委屈 1，1 分钟内再摔不重复。
7. `cmd.mood`：待机表情跟着变；断开后保持到 `until`。
8. `cmd.act`：认识的照做回 `ok`；不认识回 `unknown`；拎着时回 `busy`；1 分钟内第二个回 `rate`。
9. 没有 `"presence"` / `"mood"` / `"act"` 时：对应的消息一条都不发、收到也不认（回 `ok: false`，`code: "unsupported"`）。

### 17.9 要 bot 那边回话的

1. 三个 `features` 名字和拆法行不行。
2. `held` 的做法（回来再显示、不改发 QQ）行不行；`proactive` 的过期时间。
3. `ignored` 的「2 小时没理」只算桌面这边，bot 再按 QQ 那边过滤，行不行。
4. 没连上时的 `event.emotion` 进 `offline.batch`（`kind: "emotion"`），还是直接丢。
5. `cmd.mood` 要不要带一句给主人看的心境文字（桌宠现在不显示）。
6. `front.title` 进不进记忆、存多久。
7. `cmd.act` 每分钟最多 1 个够不够。
