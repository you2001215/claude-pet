# 桌宠 ↔ AstrBot 桌面连接 · 接口说明（草稿 v0.1）

> **给主人的一段话：** 这份是桌宠和阿鲸之间「怎么说话」的约定：发什么消息、每条长什么样、出错了怎么说。桌宠这边（本仓库）和阿鲸那边（AstrBot 的桌面适配器插件）各写各的，都对着这份测。阶段 ① 要用的部分写全了，后面阶段的先占个位置。现在是草稿，两边商量定了才改成正式版、才开始写代码。
>
> 本文件在公开仓库里，只写接口，不写主人的部署和安全细节。

- 版本：v0.1（2026-11-06，桌宠云端会话起草，待阿鲸产品经理会话审）
- 依据：工作档案总览「一起看 + 桌宠接入 10 条定稿」、「已确认的连接需求」

## 1. 分工和范围

| | 谁 | 做什么 |
| --- | --- | --- |
| 客户端 | 桌宠（Electron 主进程） | 主动连上去、配对、把桌面聊天和事件交过去、显示 bot 的回复和指令；连不上时退回自带的大脑，不报错 |
| 服务端 | AstrBot 桌面适配器插件 | 一个平台适配器，桌面是 AstrBot 里的**独立会话**（不冒充 QQ 私聊，不直接写库）；验证设备、把消息交给阿鲸、把她的回复推回来 |

阶段 ① 的范围：**连接、配对、聊天（可流式）、可靠投递、离线补交、断线重连**。记忆互通是服务端内部的事（让记忆也认桌面会话），不需要额外的消息。

## 2. 连接

- 协议：WebSocket，只用文本帧，内容是 UTF-8 的 JSON。单帧最大 1 MiB。
- 地址：桌宠设置里填，默认 `ws://127.0.0.1:6230/desktop/v1`（端口待阿鲸那边确认，要避开 AstrBot 面板和其他适配器已经占用的端口）。
- 服务端只监听 `127.0.0.1`，**绝不监听 `0.0.0.0`**。阶段 ④（另一台电脑）再加组网工具的私有地址。
- 桌宠这边只允许对本机、局域网、组网工具（`100.64.0.0/10`）地址用 `ws://`，其他地址必须 `wss://`（和 1.6.1 的接口地址规则一致）。
- 服务端在握手时检查：
  - **请求里带 `Origin` 头的一律拒绝**（浏览器里的网页连本机端口一定会带 `Origin`，桌宠的主进程不带）；
  - `Host` 必须是 `127.0.0.1:端口` 或 `localhost:端口`（防 DNS 重绑定）。
- 同一台设备同时只保留一条连接：同一个设备令牌又连上来时，服务端关掉旧的那条（关闭码 4409）。

## 3. 信封

每一帧都是一个 JSON 对象：

```json
{ "v": 1, "type": "chat.send", "id": "m_01JC8Q3Z4X", "ts": 1762400000000, "data": { } }
```

| 字段 | 说明 |
| --- | --- |
| `v` | 协议大版本，现在是 `1` |
| `type` | 消息类型，见下文 |
| `id` | 发送方生成、全局唯一，≤64 字符（UUID 或 ULID 都行）。用来去重和回执 |
| `ts` | 发送方的时间，毫秒，UTC。时区在 `hello` 里说一次 |
| `data` | 内容 |

- 收到不认识的 `type`：忽略，只记一下条数，不断开（方便以后加新类型）。
- 收到不认识的字段：忽略。
- 日志只记类型、编号、条数、长度，**不记原文**。

## 4. 握手和配对

连上以后，桌宠 10 秒内必须先发 `hello`，否则服务端断开（4408）。

### 4.1 `hello`（桌宠 → bot）

```json
{ "v": 1, "type": "hello", "id": "h_01JC8Q", "ts": 1762400000000, "data": {
  "proto": [1],
  "app": "ClaudePet", "app_version": "1.7.0", "platform": "win32",
  "device_name": "书房电脑",
  "tz": "Asia/Shanghai", "tz_offset_min": 480,
  "auth": { "token": "…" }
} }
```

- `auth` 二选一：已经配对过用 `{ "token": "…" }`；第一次配对用 `{ "pair_code": "483920" }`。
- `platform`：`win32` 或 `darwin`。
- `device_name`：主人在桌宠设置里起的名字，默认用电脑名。

### 4.2 `welcome`（bot → 桌宠）

```json
{ "v": 1, "type": "welcome", "id": "w_01JC8Q", "ts": 1762400000123, "data": {
  "proto": 1,
  "device_id": "dev_7f3a",
  "token": "…（只有这次是配对时才有）",
  "server_time": 1762400000123,
  "limits": { "text_max": 4000, "frame_max": 1048576, "batch_max": 200 },
  "features": ["chat.stream"]
} }
```

- `features`：服务端支持的可选能力。桌宠只用列出来的；没列出流式，就只等 `chat.done`。
- 时间差超过 2 分钟时，桌宠在诊断信息里记一笔（定时、分天都按各自的本机时间，不靠对方的时间）。

### 4.3 配对码和设备令牌

- 配对码：主人在 QQ 私聊发「/桌宠配对」拿到，**6 位数字，5 分钟内有效，用一次作废，只认主人**。
- 防猜：同一个配对码输错 5 次就作废；每条连接只能试 1 次，错了就断开（4403）。
- 设备令牌：配对成功时服务端生成，至少 32 字节随机数，base64url 编码。服务端**只存它的哈希**；桌宠用系统加密（safeStorage）存在本机，和 API Key 一样，不进同步盘、不进诊断信息、不放在网址里。
- 「/桌宠设备」列出设备（名字、平台、上次在线时间、编号后 4 位）；「/桌宠吊销」吊销以后，这台设备再连会收到 4401，正连着的立刻被断开。
- 桌宠收到 4401：提示「这台电脑和阿鲸的连接被撤销了，要重新配对」，停止自动重连，退回自带的大脑。

## 5. 心跳和重连

- 桌宠每 30 秒发一次 `ping`（`data` 为空），服务端回 `pong`（`data.ref` = 那条 ping 的 `id`）。10 秒没回就当断了，开始重连。
- 服务端 90 秒没收到任何帧就断开。
- 重连间隔：1、2、4、8、16、30 秒，之后一直 30 秒，每次加一点随机抖动。
- 收到 4401、4403、4426 时**不自动重连**，等主人处理。
- 连不上、断开期间：桌宠照常用自带的大脑和记忆说话，界面上只在设置页显示「阿鲸不在线」，不弹窗、不报错（连接需求第 4 条）。

## 6. 可靠投递：回执和发件箱

- 下面这些类型**必须回执**：桌宠发的 `chat.send`、`offline.batch`、以后的 `event.*`；bot 发的 `cmd.say`。
- 收到的一方处理好（服务端：交给阿鲸的会话或存进队列；桌宠：显示出来或排进气泡队列）以后回：

```json
{ "v": 1, "type": "ack", "id": "a_01JC8R", "ts": 1762400000200, "data": { "ref": "m_01JC8Q3Z4X", "ok": true } }
```

  不收的回 `"ok": false, "code": "…"`（错误码见第 10 节），发送方不再重发。
- 发送方没收到回执之前，把消息留在**发件箱**里；重连后用**同一个 `id`** 重发。收到的一方按 `id` 去重：同一个 `id` 再来，直接再回一次回执，不重复处理。去重记录至少保留 7 天。
- 桌宠的发件箱存在本机（经 `store.js`，先写临时文件再替换），最多 500 条或 7 天，超出的丢掉最旧的，只在诊断信息里记丢了几条。
- 回执只表示「收到了」，不表示「回答了」。回答走第 7 节。

## 7. 聊天

### 7.1 `chat.send`（桌宠 → bot）

```json
{ "v": 1, "type": "chat.send", "id": "m_01JC8Q3Z4X", "ts": 1762400000000, "data": {
  "text": "今天好累啊",
  "input": "text"
} }
```

- `text`：≤ `limits.text_max`（4000）字，超过的桌宠先截断。
- `input`：`text`（打字）或 `voice`（语音识别出来的，可能有错字）。
- 以后的阶段会在 `data` 里加 `context`（比如一起看时的播放点），服务端照常忽略不认识的字段。

### 7.2 回复（bot → 桌宠）

流式（`features` 里有 `chat.stream` 时）：先来若干条 `chat.delta`，最后一条 `chat.done`。不流式：只来 `chat.done`。

```json
{ "v": 1, "type": "chat.delta", "id": "d_01JC8S", "ts": 1762400001000, "data": {
  "reply_to": "m_01JC8Q3Z4X", "seq": 1, "text": "辛苦啦～"
} }
```

```json
{ "v": 1, "type": "chat.done", "id": "r_01JC8T", "ts": 1762400003000, "data": {
  "reply_to": "m_01JC8Q3Z4X",
  "merged": ["m_01JC8Q3Z4X"],
  "parts": [
    { "text": "辛苦啦～今天忙什么了？" }
  ],
  "emotion": { "name": "担心", "level": 1 }
} }
```

- `parts`：一条或几条气泡，按顺序显示。`text` 是**给人看的文字**，不带任何隐藏标记；桌宠照样过一遍 `ai-parse.js` 的 `visible()` 兜底。
- `merged`：两条消息挨得很近、bot 合起来回答时，列出合并了哪几条；不合并时就是 `[reply_to]`。
- `emotion`：可选，阿鲸的 8 个情绪名之一（开心、得意、上头、平静、无聊、烦、委屈、担心），强度 1～3。桌宠用它选表情和动作。
- `chat.delta` 的 `text` 是增量。桌宠以 `chat.done` 为准；`done` 和拼起来的 `delta` 不一样时，用 `done`。
- 出错：

```json
{ "v": 1, "type": "chat.error", "id": "e_01JC8T", "ts": 1762400003000, "data": {
  "reply_to": "m_01JC8Q3Z4X", "code": "model_failed", "retry": true
} }
```

  桌宠收到 `chat.error`：`retry` 为真时，对这一句改用自带的大脑回答，并在这一句旁边标「（阿鲸刚才没接上，这句是我自己说的）」——具体措辞到时候给主人看。

### 7.3 语音

阶段 ① 桌宠自己用 Edge / Kokoro 念 `parts[].text`，bot 不发音频。一起看时默认不念（10 条定稿第 3 条）。

## 8. bot 主动说话：`cmd.say`（bot → 桌宠）

阶段 ① 先把格式定下来，路由规则（在电脑前才发桌宠）在阶段 ③ 做。

```json
{ "v": 1, "type": "cmd.say", "id": "s_01JC9A", "ts": 1762400100000, "data": {
  "source": "proactive",
  "parts": [ { "text": "还在忙吗？" } ],
  "emotion": { "name": "平静", "level": 1 },
  "expires_at": 1762400400000
} }
```

- `source`：`proactive`（主动找你）、`reminder`（提醒）、`care`（关心睡觉吃饭）、`watch`（一起看）。
- `expires_at`：过了这个时间还没显示出来就丢掉（比如一起看时视频已经往后放了）。
- 必须回执。桌宠显示了回 `ok: true`；因为过期、全屏勿扰之类没显示，回 `ok: false` 和原因，bot 自己决定要不要改发 QQ。

## 9. 离线补交：`offline.batch`（桌宠 → bot）

bot 不在线期间，主人照样和桌宠聊（用的是桌宠自带的大脑）。重连成功后，桌宠把这段时间的对话一次交过去：

```json
{ "v": 1, "type": "offline.batch", "id": "b_01JC9B", "ts": 1762403600000, "data": {
  "from": 1762400000000, "to": 1762403500000,
  "items": [
    { "id": "m_01JC90", "ts": 1762401000000, "role": "user", "text": "我去吃饭了" },
    { "id": "m_01JC91", "ts": 1762401002000, "role": "pet",  "text": "去吧去吧，吃饱再回来～" }
  ]
} }
```

- `role`：`user`（主人说的）或 `pet`（桌宠自带的大脑说的）。
- 服务端只把这些放进时间线和记忆材料，**不当成新消息去回答**，也不触发主动消息。
- 一批最多 `limits.batch_max`（200）条，多了分几批发，每批都要回执。
- 阶段 ③ 的事件（重摔、两小时没人理……）离线期间也存着，以后放进同一个 `items` 里，用 `kind` 区分。

## 10. 错误码

### 10.1 关闭码（WebSocket close code）

| 码 | 名字 | 什么时候 | 桌宠怎么办 |
| --- | --- | --- | --- |
| 4400 | `bad_frame` | 不是 JSON、缺字段、帧太大 | 记诊断，重连 |
| 4401 | `token_invalid` | 令牌不对或已经被吊销 | 提示重新配对，**不重连** |
| 4403 | `pair_code_invalid` | 配对码错了、过期了、用过了 | 提示「配对码不对或过期了，回 QQ 再发一次 /桌宠配对」，**不重连** |
| 4408 | `hello_timeout` | 连上 10 秒没发 `hello` | 重连 |
| 4409 | `replaced` | 同一台设备又连上来一条 | 不重连（新的那条在用） |
| 4426 | `proto_unsupported` | 协议版本对不上 | 提示「桌宠或阿鲸那边需要更新」，**不重连** |
| 4429 | `rate_limited` | 发得太快 | 按 `reason` 里的秒数等一会儿再连 |
| 4500 | `server_error` | 服务端出错 | 重连 |

### 10.2 回执和 `chat.error` 里的 `code`

| `code` | 意思 |
| --- | --- |
| `too_long` | 文字超过 `text_max` |
| `duplicate` | 这个 `id` 已经处理过（同时 `ok: true`，不用重发） |
| `busy` | 阿鲸正忙，稍后再试 |
| `model_failed` | 模型出错或超时 |
| `not_allowed` | 这台设备没有这项权限 |
| `expired` | 消息已经过期（`cmd.say`） |
| `dnd` | 勿扰中没显示（`cmd.say`） |

## 11. 后面阶段预留的消息（先占位，字段到时再定）

| 阶段 | 类型 | 方向 | 内容 |
| --- | --- | --- | --- |
| ② | `event.watch` | 桌宠 → bot | 一起看的进度：视频编号、秒数、暂停、倍速、拖动、看完。合并成每 5～10 秒一条，暂停、拖动、切换、倍速立刻发 |
| ② | `event.mode` / `cmd.mode` | 双向 | 三档（安静 / 正常 / 话多）和话多档每小时上限 |
| ② | `cmd.point` | bot → 桌宠 | 她指他点：视频编号、秒数、一句话；桌宠弹「跳过去」按钮 |
| ② | `chat.send.data.context.watch` | 桌宠 → bot | 一起看时主人说话带上播放点 |
| ③ | `event.presence` | 桌宠 → bot | 在 / 不在 / 锁屏、原因、前台应用名和窗口标题（≤80 字），变了才报 |
| ③ | `event.emotion` | 桌宠 → bot | 身体刺激：重摔 → 委屈 1、两小时没人理 → 无聊 1、连戳 → 烦 2、生气时摸头消气 → 开心 1 |
| ③ | `event.care` | 双向 | `care.sleep`、`care.meal`：问过了，两边合起来数 |
| ③ | `cmd.mood` | bot → 桌宠 | 每小时的心境，桌宠待机表情跟着走 |
| ③ | `snapshot.request` / `snapshot.data` | 双向 | 快照（10 条定稿第 7 条），每小时一次，只存本机 |
| ③ | `cmd.act` | bot → 桌宠 | bot 指挥动作（动作名照 `design/亲密度与事件.xlsx` 的「动作」列） |
| 以后 | `media` | bot → 桌宠 | 表情包、图片、音频：`{ sha256, mime, size, url }`，桌宠用同一个地址和端口、带 `Authorization: Bearer <令牌>` 去取，按 sha256 校验后缓存 |

## 12. 测试约定

- 阿鲸那边写一个「假桌宠」客户端测服务端；桌宠这边写一个「假适配器」（Node 脚本，在本机起一个 WebSocket 服务）测客户端，放进 `tests/`，`npm test` 能跑。
- 两边都要过的用例：
  1. 第一次配对成功，拿到令牌；用令牌重连成功。
  2. 配对码错、过期、用过：4403，桌宠不重连。
  3. 同一个配对码输错 5 次后，用对的码也不行。
  4. 令牌被吊销：正连着的被断开，再连 4401。
  5. 同一台设备连第二条：旧的被 4409 关掉。
  6. 握手带 `Origin` 头：被拒绝。
  7. 一问一答（流式和不流式各一次），`chat.done` 以它为准。
  8. `chat.send` 发出去以后马上断线：重连后补发，服务端按 `id` 去重，只回答一次。
  9. bot 关着时聊天：桌宠用自带大脑回答；bot 回来后 `offline.batch` 补交，服务端不回答这些旧消息。
  10. 超长文字：`too_long`。
  11. 不认识的 `type` 和字段：被忽略，连接不断。
  12. 日志里查不到聊天原文和令牌。

## 13. 要两边商量的问题

1. 端口默认值和路径（第 2 节）。
2. 两台电脑（Windows 和 Mac）连上来，是**同一个桌面会话**，还是**每台一个会话**？
3. 主人在桌面上说「3 点提醒我开会」时，阿鲸怎么让桌宠记下这个提醒？提醒现在存在桌宠里，bot 没有提醒插件。建议加 `cmd.remind`（新增 / 取消），阶段 ① 就做，不然连上 bot 以后桌面上设不了提醒。
4. 表情包：阿鲸回复里要发表情包时，是 bot 发图片（第 11 节 `media`），还是 bot 只给名字、桌宠用自己的表情包清单（现在的 `[sticker:名]`）？
5. 「看看我在看什么」（截图看屏幕）连上以后交给阿鲸：截图怎么传、放在哪个阶段？
6. 两条消息挨得很近时，排队还是合并（第 7.2 节的 `merged`）？
7. 离线期间桌宠说的话，在 bot 的时间线里怎么标（工作档案日志 ⑱ 里说要标明）？
8. `chat.done` 里带不带 `emotion`？阶段 ① 带上，桌宠就能按她的情绪选表情。
